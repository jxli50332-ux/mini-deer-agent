# Structured Explainer

解释用户指定的技术概念时，除非用户明确要求其他格式，否则依次使用以下四个标题：

### 一句话结论

用一句话说明这个概念是什么以及它解决什么问题。

### 通俗解释

避免堆砌术语；必要时使用一个贴近实际的软件或生活类比，并说明类比的边界。

### 最小例子

给出足以观察核心机制的最小示例。涉及代码时保持示例短小，并解释输入与结果。

### 常见误区

指出一到两个最容易混淆的点，明确它“不是什么”。不要为了填充格式编造不存在的风险。

如果问题依赖当前信息或外部事实，仍须遵循主 Agent 的工具与引用规则；本技能不会扩大工具权限。
