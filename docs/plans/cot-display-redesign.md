## 3. 当前源码暴露的问题

1. `.app-shell` 把展开侧栏固定为 `264px`，只有展开/收起两档，没有连续宽度调整。
2. Composer 的 `textarea` 虽声明了 `resize: vertical`，却被 `max-height: 160px` 限制；附件和 Todo 增加后也缺少清晰的高度边界。
3. 普通会话在 `useThreadList` 中固定只请求 20 条；项目会话最多请求 100 条，并且 UI 默认只渲染前 5 条。
4. `project-sidebar` 和 `conversation-list` 各自拥有滚动条，项目区还可能产生横向滚动；内容增长会挤压另一块区域。
5. 项目会话保存在 `useProjects.projectThreads`，没有接入通用删除回调，也没有在删除后同步项目列表状态。
6. 项目名、项目会话、文件树、状态文字和操作文字大量使用 `0.60rem`—`0.78rem`，在高分辨率屏幕上明显过小。
7. 对话区、Todo 与 Composer 使用不同最大宽度，超宽屏上视觉中心分散，代码/变更展示空间也偏窄。
8. 当前项目身份是从“最近会话”数组反查出来的；只要当前项目会话不在首批数据中，项目激活态和 Benchmark 的项目判断就可能失真。

## 5. 详细设计

### 5.1 桌面侧栏左右拉伸

- 在侧栏右边缘增加真实拖拽条，而不是把鼠标样式伪装成可拖拽。
- 默认宽度 `280px`，允许范围 `240px`—`480px`，同时不能超过视口宽度的 `45%`。
- 通过 CSS 变量 `--rail-width` 驱动 `.app-shell` 的网格列宽；拖拽时只更新布局状态，不直接查询或修改业务数据。
- 展开宽度写入 `localStorage`。收起仍使用现有 `72px` 窄轨；再次展开恢复最后一次有效宽度。
- 折叠和移动抽屉状态下隐藏拖拽条。移动端继续使用固定抽屉宽度，不复用桌面宽度，避免小屏被历史设置占满。
- 拖拽条使用 `role="separator"`、`aria-orientation="vertical"`，支持方向键微调、`Home` 恢复最小值、`End` 到最大值、双击恢复默认值。
- Pointer 生命周期必须在结束或卸载时释放；拖拽期间禁用文本选择，结束后恢复，不能遗留全局样式。

### 5.2 输入框上下拉伸

- 在文本编辑区上沿增加可见但低干扰的水平拖拽条，拖动方向与底部固定的 Composer 一致：向上增高、向下缩小。
- 编辑区默认高度 `88px`，最小 `64px`，最大为 `min(42dvh, 420px)`；到达上限后只在文本区内部滚动，不能把消息区完全挤走。
- 高度由 CSS 变量 `--composer-editor-height` 控制；采用显式拖拽后关闭浏览器原生角落缩放，避免两套高度机制互相覆盖。
- 高度偏好在设备本地保存，并跨 Thread 保留；切换会话不应让输入框突然回到默认高度。
- 拖拽条同样提供键盘调整与双击复位。禁用、发送中、停止中仍保留既有按钮语义。
- Todo、附件和错误提示保持自然高度；只有正文编辑区参与手动拉伸。Composer 总高度超过安全范围时，其辅助内容内部收敛，聊天区始终保留可用空间。

### 5.3 侧栏单一滚动区

侧栏调整为下面的结构：

```text
固定：品牌、折叠按钮
固定：新会话入口
滚动：项目列表、项目会话、文件树、普通会话、加载状态
固定：本地环境状态
```

- 新增统一的 `.conversation-rail__scroll-region`，设置 `min-height: 0`、`overflow-y: auto`、`overscroll-behavior: contain` 和稳定滚动条槽位。
- 移除 `project-sidebar` 的 `max-height: 42dvh` 与 `conversation-list` 的独立纵向滚动；侧栏只出现一根纵向滚动条。
- 统一设置 `overflow-x: hidden`、`min-width: 0`、省略号和可换行边界。项目路径与文件名不再撑出截图中的横向滚动条。
- `html/body/app-shell` 维持视口高度且不因侧栏内容增长产生页面级滚动；鼠标滚轮停留在侧栏时只滚动侧栏。
- 切换项目、删除会话和加载下一页时尽量保留现有 `scrollTop`，不能每次回到顶部。

### 5.4 所有会话与分页

“展示所有”定义为：任何持久会话都能通过同一侧栏滚动到达，不再被 20 条、5 条或 100 条硬截断；数据按页加载，避免首屏一次请求全部历史。

#### 服务端最小配套

- `GET /api/v1/threads` 增加向后兼容的 `offset` 和 `scope=standalone` 查询参数；缺省行为保持原契约。
- `GET /api/v1/projects/{project_id}/threads` 增加 `offset`。
- Repository 查询统一使用稳定顺序 `updated_at DESC, thread_id DESC`，并接收 `limit + offset`。
- 继续返回数组，客户端以“返回条数小于页大小”判断结束；恰好整页时允许一次安全的空页探测，不引入破坏性响应结构变更。

#### 客户端行为

- 普通会话使用 50 条一页，`useThreadList` 增加 `hasMore`、`isLoadingMore`、`loadMore`，追加时按 `threadId` 去重。
- 普通列表请求 `scope=standalone`，不再先取混合列表再在浏览器过滤，避免前 20 条全是项目会话时普通列表看起来为空。
- 当前 Thread 的 `projectId` 改由已有 `GET /api/v1/threads/{thread_id}` 单独读取；项目激活态和 Benchmark 不再依赖一个有界的导航列表。
- 项目展开后直接显示全部已加载会话，删除现有 `.slice(0, 5)` 和“展开显示”开关；项目会话也以 50 条一页继续加载。
- 项目登记列表已经具有分页状态，但侧栏没有入口；补充“加载更多项目”，确保第 21 个项目及其会话可达。
- 接近滚动区底部时自动加载下一页，同时保留可聚焦的“加载更多”按钮作为键盘、测试和失败重试入口。
- 加载下一页失败只显示局部错误，不清空已经加载的会话；刷新则从第一页重建并去重。
- 本轮不引入虚拟列表依赖。分页先控制首屏和网络成本；若真实数据达到数百条后出现可测量卡顿，再单独评估 DeerFlow 的 60 项阈值虚拟化方案。

### 5.5 项目会话删除与状态同步

- 项目会话行增加删除入口，确认文案明确显示会话标题，不允许单击直接删除。
- 复用现有 `DELETE /api/v1/threads/{thread_id}`，不新增“项目删除会话”专用接口；Thread 归属不改变生命周期语义。
- 只有服务端返回 `204` 后，才从当前项目的 `projectThreads`、当前 Thread 元数据及其他可能命中的会话缓存中移除；失败保留原行并允许重试。
- `busy`、后台运行或当前 Run 正在停止的会话禁用删除，并给出可读原因。
- 删除当前项目会话成功后，沿用现有逻辑创建一个新的普通 Thread；项目、目录和文件不受影响。
- 删除空白的刚创建项目会话继续与 `useProjectThreadDraft` 的离开清理协作，不能重复发起 DELETE。
- 普通会话和项目会话统一选择、当前态、运行态、确认删除和错误反馈契约；项目列表在服务端成功后同步自己的分页缓存。
- 本轮顺带让项目会话接入已有改名能力；改名或删除成功后，用服务端返回事实更新对应列表，而不是只改 DOM 文本。

### 5.6 字体、密度与内容宽度

- 侧栏建立三档可读层级：项目名和会话标题 `14px`；状态、时间与辅助信息 `12px`；分区标题 `11px`—`12px` 且不使用过大的字距。
- 文件树正文至少 `12.5px`，操作按钮至少 `12px`，触控/点击热区不小于 `32px`；不再使用 `0.60rem` 的关键状态文字。
- 项目行与普通会话行统一圆角、左右内边距、选中竖线、hover/focus 和运行状态。改名/删除在鼠标悬停或键盘聚焦时显现，触屏环境始终可见。
- 使用共享 `--workspace-content-width` 对齐 Goal、消息内容容器、Todo 和 Composer，初始值定为 `960px`；代码 diff 可以占满该容器，普通正文继续使用可读行长而不是铺满超宽屏。
- 统一低对比边框与森林绿状态色，保留现有视觉身份；不进行主题重写，也不新增图标库。
- 空会话提示改为符合当前 Coding 能力的示例，不再只提示天气工具。

### 5.7 响应式与可访问性

- `800px` 以下继续使用抽屉式侧栏；桌面拖拽宽度和折叠偏好不能改变移动抽屉尺寸。
- 小屏输入区最大高度降为 `35dvh`，按钮和附件区允许换行，软键盘出现时仍能看到发送/停止按钮。
- 所有拖拽都必须有键盘等价操作、焦点样式和准确 ARIA 数值；`prefers-reduced-motion` 下关闭宽度动画。
- 侧栏、列表和 Composer 的错误提示使用现有 `role="alert"/"status"` 语义，分页追加不能抢走当前焦点。

### 5.8 侧栏导航增强

- 在侧栏顶部统一检索普通会话与项目会话；关键词同时匹配会话标题、Thread ID 与项目名，并提供全部、运行中、项目会话、普通会话四种范围及最近、最早、标题三种排序。
- 默认导航保持项目树与最近会话两层结构；筛选开启时切换为单一结果列表，避免同一会话重复出现。搜索、范围和排序偏好写入本地存储。
- 项目保持单展开，刷新后恢复最后展开项；支持本地置顶，置顶项稳定排在普通项目之前。项目行展示会话总数与运行指示，当前会话所属项目和当前会话采用更强选中态。
- 普通与项目会话统一为两行信息结构，并把改名/删除收进紧凑操作菜单。项目操作区固定宽度，标题随侧栏宽度省略，因此超长项目名或会话名不会挤掉新建按钮。
- 长标题悬停或键盘聚焦后显示延迟多行浮层；浮层文本使用 `aria-hidden`，避免屏幕阅读器在已有按钮名称之外重复朗读。触屏环境不依赖悬停，操作入口始终可见。
- 项目与最近会话分区标题保持粘性；加载、空结果和失败使用一致的骨架、状态与重试样式。长列表通过 `content-visibility: auto` 跳过离屏渲染，不增加虚拟列表依赖。
